# Graph Communities

[English](README.md)

Graph Communities 会把 Obsidian 的黑白关系图谱变成一张按知识点组织的彩色知识地图。
插件从每篇本地文章中提取多个知识点，以主知识点形成分类，并用其余知识点、元数据和链接关系增强关联。
每个主知识点拥有稳定颜色；同一知识领域使用相邻色相，次知识点和链接关系会让相关笔记呈现相近或自然混合的颜色。

## 主要功能

- 在本地读取每篇笔记的有限正文片段，识别学术、项目、参考资料及 Prompt/Skill 等用途。
- 为每篇文章生成多标签知识画像，不再把文章名称或目录名称当成主要索引。
- 覆盖儿童发展、心理学、教育学、语言、习惯、运动、儿童交互、安全、AI 工程、数据治理、产品、市场和硬件等知识点。
- 识别大语言模型、AI 系统、Agent、语音、合规、硬件、市场与产品策略等主题。
- 将 Desktop、Shared Knowledge、Resources 等通用存放目录视为位置，而不是分类名称。
- 将 Product Manager 资料合并为四个紧凑分类：PM Strategy & Discovery、PM Execution & Growth、PM Data & Tools、PM Prompts。
- 突出 PM Skill 包中的主 `SKILL.md` 定义；重复包与辅助资料只降低视觉比重但保留分类色，图例仍会显示“主版本数 / 总数”。
- PM 按关键词保留一份 canonical Skill 或 Prompt/Workflow 代表，归入四个低权重子分类；重复仓库和辅助文件不进入图谱。
- 其他文章按正文知识点分类；桌面目录名只作为缺少正文证据时的兜底信息。
- 将儿童陪伴机器人项目统一放在红色的“儿童陪伴机器人（工作）”父分类下；语言发展、心理学、习惯形成、运动发展、儿童交互、安全、合规、硬件等知识点使用固定的红、玫红、粉红、紫红色阶。
- 全局知识领域使用高区分度稳定色带：儿童发展与教育为珊瑚/橙色，产品与商业为亮黄/琥珀色，硬件与具身为绿色，AI 与工程为蓝/青色，治理与证据为紫色，交互与安全为玫红/品红色；领域之间同时拉开色相和明暗差。
- 使用正文、标签、别名、标题层级、链接及低权重路径提示作为分类信号。
- 支持 `AI`、`LLM`、`ASR` 或自定义项目名等优先关键词。
- 自动降低 README、index、导航、概览、资源页等通用文件的权重。
- 优先选择有实际主题含义的笔记作为代表节点，而不是导航文件。
- 为不同大型枢纽分配适合深色主题的不同主色。
- 沿邻接关系传播颜色，使关系越紧密的节点颜色越相近。
- 对连接多个社区的桥接节点进行颜色混合。
- 根据两端节点颜色绘制连线，并弱化跨社区连线。
- 同时支持全局图谱和局部图谱。
- 可选图例会显示人类可读的主题/项目名称和节点数量。
- 图谱文件节点默认显示为“父文件夹 / 文件名”，例如 `Projects / README`，避免多个 README、index 等同名文件无法区分。
- 图谱节点与分类图例会双向联动：打开节点时选中对应分类；点击左侧分类时，右侧对应节点保持原始分类色和 100% 不透明度，内部连线同步强化。
- 支持父分类与子分类联动：点击项目父分类会聚焦全部子类，打开具体笔记时会同时标记父分类和对应子分类。
- 打开图谱节点时会显著提亮目标节点和对应分类、强化相连边，并通过降低透明度弱化其他节点，但保留其原本色相；主动点击分类时会进一步聚焦该分类。
- 所有计算都在本地完成，不修改笔记内容。

## 视觉规则

```text
蓝色枢纽 ─ 蓝色节点 ─ 蓝紫桥接节点 ─ 紫色节点 ─ 紫色枢纽
```

节点大小仍由 Obsidian 控制，插件只改变颜色：

- **主色**：表示所属知识社区。
- **领域色带**：不同知识领域保持明显色差，同领域知识点使用不同深浅的近邻色。
- **颜色相似度**：表示图关系的相似程度。
- **混合色**：表示连接多个社区的边界节点。
- **柔和中性色**：表示孤立或暂时无法分类的笔记。

## 交互式聚焦

- 悬停图谱节点时，图例会立即预览并标记对应分类；点击节点并打开笔记后，该分类会保持选中状态，节点也会进一步突出。
- 点击图例中的分类，右侧该分类的全部节点会保持原始分类色和 100% 不透明度，内部连线保持原色并强化；无关节点和连线会显著变淡。此操作不改变节点大小、坐标或图谱布局。
- 再次点击当前分类，或运行 **Graph Communities: Clear graph community focus**，即可恢复完整图谱。
- 当前选中的笔记名称会显示在分类图例上方。

## 安装方式

### 从 Release 手动安装

1. 从最新 Release 下载 `main.js`、`manifest.json` 和 `styles.css`。
2. 新建 `<知识库>/.obsidian/plugins/graph-communities/` 文件夹。
3. 将三个文件复制到该目录。
4. 重启 Obsidian。
5. 进入 **设置 → 第三方插件**，启用 **Graph Communities**。

### 本地开发安装

项目除了 Node.js 外没有其他构建或运行依赖：

```bash
npm run verify
node scripts/install-local.mjs /path/to/vault --enable
```

安装新构建后需要重启或重新加载 Obsidian。

## 推荐初始设置

| 设置 | 默认值 | 作用 |
| --- | ---: | --- |
| 最大社区数量 | 24 | 限制可见主知识点数量；支持在设置中提高到 36 |
| 最小社区规模 | 2 | 合并小碎片或将其显示为中性色 |
| 主题感知聚类 | 开启 | 综合本地正文用途、主题、元数据与链接 |
| 优先主题关键词 | 儿童发展、教育学、心理学、语言发展、习惯养成、运动发展、AI、LLM、ASR、RAG、Agent | 强化指定主题的聚类与命名 |
| 内容分类凝聚力 | 5.0 | 让用途与主题相同的笔记保持聚集 |
| 主题相似度影响 | 1.4 | 让推断标签与本地元数据相似的笔记更接近 |
| 聚类分辨率 | 1.0 | 越低社区越少越大，越高社区越多越细 |
| 关系混合强度 | 0.52 | 越高，跨链接的颜色混合越明显 |
| 混合距离 | 4 | 颜色沿多少层链接传播 |
| 弱化外围节点 | 0.18 | 让大型枢纽更加突出 |
| 图谱标签显示父文件夹 | 开启 | 将文件节点显示为“父文件夹 / 文件名”，不改变文件真实路径 |

大量调整链接后，可以运行命令：
**Graph Communities: Recompute graph communities**。
插件也会在元数据索引完成或 Markdown 文件变化后自动重新计算。

## 算法原理

1. 通过 Obsidian 本地知识库 API 读取每篇 Markdown 最多前 24,000 个字符，并按文件版本缓存。
2. 从正文与元数据推断“学术 / 项目 / 参考资料”等用途，以及多个主题标签。
3. 用维护的知识点本体对正文、标题层级、别名和标签评分；每篇文章最多保留八个知识点及命中证据词。
4. 将 PM 内容合并为四个子分类，每个关键词只保留一份 canonical 代表并降低图谱权重。
5. 将通用目录和文件名降为兜底提示，而不是主要分类依据。
6. 综合知识点重合、语义相似度和降权后的导航链接，同时保留项目与学术多样性。
7. 对 README、index 等导航文件施加强降权，选择更有主题含义的代表笔记。
8. 按知识领域分配固定色带，并让每个主知识点在领域色带中占据稳定色位。
9. 用次知识点对文章主色做小幅混合，再在指定链接层数内传播社区亲和度。
10. 根据每个节点的知识画像和社区亲和度在线性 RGB 空间混合颜色，形成自然过渡色。

该模型会在本地读取有限正文片段，但不调用云端嵌入模型，也不会上传知识库内容。

## 隐私与安全

- 全部计算在 Obsidian 本地完成。
- 不发送网络请求，不收集分析数据，不需要 API Key。
- 不创建、修改、移动或删除笔记。
- 插件设置使用 Obsidian 标准插件数据机制保存。
- 禁用或卸载插件后，会恢复主题原本的节点颜色。
- GitHub Release 只包含 `main.js`、`manifest.json` 和 `styles.css`，不会打包 Vault 笔记、生成索引、本地路径或插件设置。
- 发布边界和漏洞报告方式见 [SECURITY.md](SECURITY.md)。

## 兼容性说明

Obsidian 暂未通过公开插件 API 提供逐节点着色能力，因此本插件与其他图谱着色插件一样，
需要访问图谱渲染器的内部节点和连线对象。未来 Obsidian 升级后可能暂时需要兼容更新；
即使出现兼容问题，也只会导致颜色不显示，不会影响知识库内容。
